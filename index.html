STREAMX Update Rules

  • Official source only: updates must come from the verified STREAMX HTTPS domain or official app store listing. Never install an unknown APK.
  • Versioning: use MAJOR.MINOR.PATCH (example: 2.1.0). Preview builds must be labelled Preview/Beta and must not be presented as stable releases.
  • Compatibility: publish separate Android Mobile and Android TV builds when device controls or layouts differ; Web/PWA updates are served from the web host.
  • Mandatory update: require an update only for a verified critical security, compatibility or service issue. Otherwise updates remain optional.
  • Staged rollout: test internally first, then release to a small group, then expand. Keep the previous known-good build for rollback.
  • Data safety: back up cloud data before migrations. Never delete user playlists, favourites or history as a routine update action.
  • TV edition: ad-free app interface. Android Mobile may show ads only after a compliant ad SDK, consent and privacy disclosures are configured.
  • Security: Firebase rules and server authorization—not UI visibility—must enforce account, admin, ban and lock permissions.
  • Network/player: do not promise “no lag” or fixed “9990+” speeds. Show measured connection information and adapt buffering to the actual network.
  • Release notes: every published update must list version, date, supported platforms, changes, known issues and rollback/build reference.

These are product/release policies. They do not publish an update or configure Firebase, ad services, app-store signing, or a backend by themselves.

“Latest update” means the version recorded in this template; change the version/date only when you publish a real release. No automatic release verification is connected.
